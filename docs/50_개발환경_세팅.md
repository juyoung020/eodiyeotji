> 대상: Pleos Connect(Android Automotive) 앱, Kotlin + Rust 네이티브 코어(JNI)
> 세팅일: 2026-11-05 · 머신: Windows 11 Home, i5-11400H, RAM 16GB, RTX 3050 Laptop 4GB
> 공모전 요구사항: **minSdk 28 이상, Gradle 8.0 이상, Java/Kotlin**

## 팀원용: 한 번에 설치

저장소를 받은 뒤 PowerShell에서:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-dev.ps1            # 설치 + 검증
powershell -ExecutionPolicy Bypass -File scripts\setup-dev.ps1 -CheckOnly # 설치 없이 확인만
```

- 아래 1절과 **같은 버전**을 설치한다: JDK(17+ 없으면 Temurin 17), Android cmdline-tools, platform-tools, emulator, platforms/android-35, build-tools/35.0.0, NDK 27.3.13750724, CMake 3.22.1, Android Studio, MSVC C++ Build Tools(Rust 링커용, 없을 때만), Rust stable + Android 타깃 3개 + cargo-ndk. 사용자 환경변수(`ANDROID_HOME`, `ANDROID_SDK_ROOT`, `ANDROID_NDK_HOME`, PATH)도 설정한다.
- **이미 있는 것은 건너뛴다** (여러 번 실행해도 됨). 마지막에 항목별 PASS/FAIL 표를 출력한다.
- 걸리는 시간: 빈 PC 기준 약 **30~60분** (네트워크 속도에 따라 다름, NDK·Android Studio·Build Tools가 대부분).
- 필요한 디스크: 도구만 약 **10GB**. Pleos 에뮬레이터까지 쓰려면 **+15GB 이상** → **총 30GB 이상 여유** 권장.
- winget 설치(JDK, Android Studio, Build Tools, rustup) 중 **관리자 권한 창(UAC)이 뜨면 "예"**를 누른다.
- 끝나면 **새 터미널**을 연다 (PATH 반영).
- 자동으로 못 하는 것 → 스크립트가 마지막에 안내를 출력한다:
  1. **Pleos Connect Emulator 이미지 설치 + AVD 생성** (Android Studio GUI, 로그인 불필요) → 7-2절
  2. Android Studio 첫 실행 마법사 → 7-5절

## 4. 빌드 방법

```bash
# 프로젝트 루트에서 (Git Bash)
./gradlew.bat assembleDebug
# PowerShell
.\gradlew.bat assembleDebug
```

- `local.properties`가 없으면 `ANDROID_HOME`을 쓴다. 직접 쓸 때는 **슬래시로** 적는다: `sdk.dir=C:/Users/rlawn/AppData/Local/Android/Sdk`
  (역슬래시 1개로 쓰면 `\U`가 이스케이프로 먹혀서 "파일 이름, 디렉터리 이름 또는 볼륨 레이블 구문이 잘못되었습니다" 에러가 난다.)
- 결과 APK: `app/build/outputs/apk/debug/app-debug.apk`

### Rust 네이티브 라이브러리 (cargo-ndk)

**따로 빌드하지 않는다.** `gradlew assembleDebug`를 하면 Gradle의 `cargoNdkBuild` 작업이 Rust 코어를 빌드해 `app/build/rustJniLibs/`에 넣고, UniFFI 바인딩까지 만든다 (`app/build.gradle.kts`).

- `x86_64` = Pleos 에뮬레이터(Windows용 이미지는 x86_64), `arm64-v8a` = 실차/실기기
- NDK는 `ANDROID_NDK_HOME`(27.3)을 자동으로 찾는다.
- ⚠️ 예전 방식처럼 `cargo ndk ... -o ../app/src/main/jniLibs`로 직접 넣으면, Gradle이 만든 것과 같은 `.so`가 두 군데 생겨서 `Duplicate resources`로 빌드가 실패한다. 이미 만들었다면 `app/src/main/jniLibs/` 폴더를 지우고 다시 빌드한다.
- Rust 로직만 확인할 때는 `cd core-rs && cargo test` (기기 없이 실행).

### SDK 패키지 추가 설치

새 CLI는 패키지 구분자로 `;` 대신 **`/`**를 쓴다 (`;`를 쓰면 "Package ... not found").

```bash
sdkmanager "platforms/android-34" "build-tools/36.1.0"
sdkmanager --list_installed
```

## 6. uniffi

`uniffi-bindgen` 바이너리는 따로 설치하지 않았다. uniffi 공식 권장 방식은 **프로젝트 안에 bindgen용 바이너리를 두는 것**이다 (`core-rs`에 `uniffi = { version = "...", features = ["cli"] }` + `src/bin/uniffi-bindgen.rs`에서 `uniffi::uniffi_bindgen_main()`). 이렇게 하면 라이브러리와 bindgen 버전이 항상 같다.

```bash
cargo run --bin uniffi-bindgen generate --library target/x86_64-linux-android/release/libxxx.so --language kotlin --out-dir ../app/src/main/java
```

## 7. 사용자가 직접 해야 하는 것 (수동 단계)

### 7-1. ⚠️ 디스크 공간 확보 (가장 먼저)

C: 드라이브 여유 공간이 **약 6.7GB** 남았다 (드라이브는 C: 하나뿐). Pleos Connect Emulator 이미지는 **zip만 4.1GB**(`crp_car_emulator.zip`, 4,087,751,964 bytes)이고, 압축을 풀면 그 몇 배가 되며 AVD 데이터 디스크도 따로 생긴다. **최소 15~20GB는 비워야** 설치와 실행이 가능하다.

### 7-2. Pleos Connect Emulator 설치 (Android Studio GUI, 공식 방법)

계정 로그인은 필요 없다 (업데이트 사이트 XML과 zip 모두 공개).

1. Android Studio 실행 → **Tools > SDK Manager > SDK Update Sites** → `+`
   - Name: `Pleos Connect System Image`
   - URL (Windows): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
2. **SDK Platforms** 탭 → 하단 **Show Package Details** 체크 → Android API 34 아래 **Pleos Connect v2.1.0 APIs Intel x86_64 Atom System Image** 체크 → OK (라이선스: 42dot Pleos Connect SDK License 동의)
   - 설치 경로: `Sdk\system-images\android-34\pleos_car_emulator\x86_64`
3. Android Studio 재시작
4. **Tools > Device Manager > Create device** → Form Factor **Automotive** → **Pleos Connect v2.1.0** → Next
5. **Advanced Settings**: Startup > Default boot = **Cold** (Quick boot면 VHAL이 안 됨), RAM = **4 GB**
6. API **34** → **Pleos Connect v2.1.0 APIs** 선택 → Finish

### 7-2-1. (대안) Android Studio 없이 명령줄로 설치

GUI의 "SDK Update Sites"는 `~/.android/repositories.cfg`에 저장소를 추가하는 것과 같다. 아래대로 하면 sdkmanager · avdmanager만으로 설치된다 (2026-11-06 노트북에서 확인, 다운로드 약 4.1GB).

1. `%USERPROFILE%\.android\repositories.cfg`에 Pleos 저장소 추가 (없으면 새로 만든다)
   ```ini
   ### User Sources for Android SDK Manager
   count=1
   disp00=Pleos Connect System Image
   dist00=
   enabled00=true
   src00=https\://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml
   ```
   → `sdkmanager --list`에 `system-images;android-34;pleos_car_emulator;x86_64`가 보이면 된다.
2. 이미지 설치 (42dot Pleos Connect SDK License 동의 필요)
   ```powershell
   sdkmanager "system-images;android-34;pleos_car_emulator;x86_64"
   ```
3. AVD 만들기 — 기기 프로필 `Pleos_Connect_v2_0`(2560×1440)은 이미지 안 `devices.xml`에 들어 있다
   ```powershell
   avdmanager create avd -n Pleos_Connect_v2.1.0_API_34 -k "system-images;android-34;pleos_car_emulator;x86_64" -d Pleos_Connect_v2_0
   ```
4. `%USERPROFILE%\.android\avd\Pleos_Connect_v2.1.0_API_34.avd\config.ini`에서 GUI의 Advanced Settings와 같게 맞춘다
   ```ini
   hw.ramSize=4096
   fastboot.forceColdBoot=yes
   fastboot.forceFastBoot=no
   ```
5. 실행은 7-3과 같다 (`scripts\emu.ps1`은 이름에 `Pleos`가 들어간 AVD를 찾는다).

### 7-3. 에뮬레이터 실행 / Virtual Console

```powershell
powershell -ExecutionPolicy Bypass -File scripts\emu.ps1     # 실행 + 부팅 대기 + Virtual Console 포트 연결
# 브라우저에서 http://127.0.0.1:8088/
```

스크립트가 하는 일 (직접 할 때):

```bash
emulator -avd <AVD이름> -no-snapshot -feature -QuickbootFileBacked   # cold boot
adb wait-for-device
adb forward tcp:8088 tcp:8088                                        # Virtual Console
```

- `-feature -QuickbootFileBacked`: 이 옵션이 없으면 에뮬레이터가 RAM 크기만큼(4GB+) 파일을 `~\.android\avd\<AVD>\snapshots\`에 만든다. 디스크가 빠듯하면 꼭 붙인다.
- AVD 데이터(`userdata-qemu.img.qcow2`)는 쓰면서 3GB 정도까지 늘어난다.

### 7-3-1. 차량 상태를 스크립트로 바꾸기 (`scripts\vc.ps1`)

Virtual Console 웹 페이지가 쓰는 HTTP API를 그대로 부른다. 주행 / 정차 전환을 손 대신 재현할 때 쓴다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\vc.ps1 -Gear Drive -Speed 40   # 주행 (Driving State 2)
powershell -ExecutionPolicy Bypass -File scripts\vc.ps1 -Speed 0 -Gear Park      # 정차 (Driving State 0)
powershell -ExecutionPolicy Bypass -File scripts\vc.ps1 -Geo 37.7905,128.9150     # 위치 넣기 (위도,경도)
powershell -ExecutionPolicy Bypass -File scripts\vc.ps1 -State                    # 현재 상태
```

| API | 내용 |
|---|---|
| `POST /browser/session?client=<ID>` | 세션 활성화. 약 3초 유지되고, 활성 세션이 없으면 다른 API가 `{"error":"emulator_inactive"}` |
| `GET /vehicle/gear?gear=Park\|Reverse\|Neutral\|Drive` | 기어 |
| `GET /vehicle/controls?speed=<km/h>&accelerator=<%>&brake=<%>` | 속도 · 페달 |
| `GET /vehicle/state`, `GET /vehicle/catalog` | 현재 상태, 조작 가능한 항목 63개 |

### 7-3-1-1. 시연 주행 재생 (`scripts
eplay.ps1`)

실제 도로를 따라가는 시연 코스를 에뮬레이터에 재생한다 (주행 구간은 기어 D + 위치 1초 간격, 정차 구간은 기어 P). 코스 데이터와 형식은 `scripts/demo-routes/README.md`.

```powershell
powershell -ExecutionPolicy Bypass -File scripts
eplay.ps1 -List                                      # 코스 목록
powershell -ExecutionPolicy Bypass -File scripts
eplay.ps1 -Scenario seoul-short -Speed 10             # 서울 짧은 코스, 10배속 (약 3분)
powershell -ExecutionPolicy Bypass -File scripts
eplay.ps1 -Scenario gangneung-day -Speed 10 -MinStopMinutes 11   # 정차를 11분 이상 유지 → 머문 곳이 잡힌다
```

- 배속을 올리면 기기 시각 기준 주행 시간이 그만큼 짧게 기록된다. 머문 곳은 실제 10분 이상 정차해야 잡히므로 `-MinStopMinutes 11`을 쓴다.
- Ctrl+C로 멈춰도 기어 P · 속도 0으로 정리된다.

### 7-3-1-2. 오프라인 지도 파일 (`scripts\map\`)

지도 파일(`korea-demo.pmtiles`, 약 60MB)은 git에 올리지 않는다. 처음 한 번 만들고 에뮬레이터에 넣는다 (자세한 내용은 `scripts/map/README.md`).

```powershell
powershell -ExecutionPolicy Bypass -File scripts\map\build-map.ps1   # 서울·서울→강릉·강릉 구간 잘라내기 → scripts\map\out\
powershell -ExecutionPolicy Bypass -File scripts\map\push-map.ps1    # 앱 폴더로 복사 (디버그 빌드가 설치돼 있어야 함)
```

- 에뮬레이터 앱은 사용자 10으로 돌고 user 빌드라서, 파일은 `run-as app.eodiyeotji --user 10`으로 `files/map/`에 넣는다 → **디버그 빌드**가 깔려 있어야 한다. `adb install -r`(덮어쓰기)는 파일을 지우지 않지만, 앱을 지우면 다시 넣어야 한다.
- 지도 파일이 없으면 앱은 바탕색 위에 경로·핀만 그리고 "오프라인 지도 파일 없음"을 띄운다.
- 에뮬레이터에서 지도를 끌어 움직이면 약 20~30fps다. 지도 글자(라벨)를 빼면 60fps가 나오므로 글자 그리기가 원인이다 (2026-11-05 측정, 아래 표).

### 7-3-2. 에뮬레이터에서 확인한 동작 (2026-11-05, Pleos Connect 2.1.0)

| 항목 | 결과 |
|---|---|
| 화면 | 2560×1440. 왼쪽 853px은 Driving view(고정), 앱 영역은 1682×1210 (넓게 쓸 때) / 세로 창 약 841×1210 (둘로 나눌 때) |
| 앱 실행 | Pleos 런처가 앱을 자기 창 안에 띄운다. `adb shell am start`만으로는 앞에 안 보이고, 아래 독의 앱 아이콘을 눌러야 보인다 |
| 주행 상태 | 기어 D + 속도 40km/h → Driving State 2(주행), `CarUxRestrictions` 0x50 (NO_SETUP · NO_VIDEO). 기어 P + 0km/h → 0(정차) |
| 주행 중 일반 앱 | DO(`distractionOptimized`)를 선언하지 않은 앱은 주행 중 "주행 중에는 사용할 수 없습니다." 화면으로 가려진다 |
| 시동 | Virtual Console에 시동(IGNITION) 항목이 없다 → 시동 기준 동작은 기어 P↔D로 대신 시연한다 |
| 위치 | `adb emu geo fix <경도> <위도>` 값이 Pleos FusedLocation 서비스에 그대로 들어간다 |
| 지도 프레임 | 지도를 끄는 동안 SurfaceFlinger timestats: 시연용 스타일(레이어 33개) 프레임 간격 대부분 31~54ms, 글자 레이어를 모두 빼면 중앙값 16ms(60fps). 가만히 있을 때는 다시 그리지 않음 |
| 셸 명령 | user 빌드라서 `cmd car_service get-property-value`는 막혀 있다. 상태 확인은 `dumpsys car_service --services CarDrivingStateService`로 한다 |

- 언어 변경: 에뮬레이터 안 **차량 설정 > 일반 설정 > 언어/Language**
- STT 테스트: Extended Controls > Microphone에서 호스트 오디오 입력 허용

### 7-4. ⚠️ GPU 사양

공식 문서상 Pleos Connect Emulator **최소 사양은 RTX 3060 Laptop 6GB**인데, 이 노트북은 **RTX 3050 Laptop 4GB**라 최소 사양보다 낮다. 실행은 될 수도 있지만 느리거나 그래픽이 깨질 수 있다. 안 되면:
- AVD 설정에서 Graphics를 `Hardware`/`Software` 바꿔 보기
- 다른 팀원 PC(사양 충족)에서 에뮬레이터를 돌리기

### 7-4-1. 데스크톱 세팅 기록 (2026-11-05)

머신: Windows 11 Pro, RTX 5070 Ti 16GB (에뮬레이터 최소 사양 충족 → **2차 PT 시연 PC 후보**), RAM 62GB.

- `scripts\setup-dev.ps1`로 JDK(기존 21) · SDK · NDK · CMake · Rust 타깃 · cargo-ndk 설치, 검증 표 전부 PASS.
- Android Studio는 winget 설치가 "Successfully installed"를 출력하고도 실제로 설치되지 않았다 → 공식 zip(`android-studio-rabbit2-windows.zip`, SHA-256 공식 값 일치)을 `%LOCALAPPDATA%\Programs\android-studio`에 풀어 설치. 관리자 권한이 필요 없다.
- Pleos 이미지는 Android Studio 대신 명령줄로 설치했다. 디스크가 빠듯할 때 쓰는 방법:
  1. 7-2의 XML이 가리키는 `crp_car_emulator.zip`(4.1GB, SHA-1 `b4f858d5bcc6c71506d7edfc872bcb9e5a11acaa`)을 받는다.
  2. `Sdk\system-images\android-34\pleos_car_emulator\x86_64\`에 압축을 푼다. `system.img`가 18GB인데 대부분 0이라, NTFS sparse 파일로 풀면 실제 사용량이 약 6GB다.
  3. 같은 폴더에 XML의 `remotePackage` 정보로 `package.xml`을 만들고, `~\.android\avd\`에 AVD(`config.ini`: `image.sysdir.1=system-images\android-34\pleos_car_emulator\x86_64\`, `tag.id=android-automotive`, `hw.ramSize=4096`, `hw.lcd.width=2560`, `hw.lcd.height=1440`, `hw.lcd.density=160`, `fastboot.forceColdBoot=yes`)를 만든다.
  4. `emulator -list-avds`에 보이고, cold boot 약 33초, `ro.build.fingerprint = Pleos/crp_avd/...release_connect_v2.1.0` 확인.

### 7-5. Android Studio 첫 실행

- 시작 메뉴 **Android Studio** (또는 `%LOCALAPPDATA%\Programs\android-studio\bin\studio64.exe`)
- 첫 실행 Setup Wizard에서 SDK 위치를 **`C:\Users\rlawn\AppData\Local\Android\Sdk`**(이미 설치된 것)로 지정하고, 추가 다운로드는 최소로 한다 (디스크 부족).
- zip 배포본이라 자동 업데이트는 Android Studio 안의 업데이트 알림으로 한다.
