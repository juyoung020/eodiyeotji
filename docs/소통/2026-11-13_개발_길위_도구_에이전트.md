# 길 위 도구 에이전트 ("나 똥마려" → 경로 앞 휴게소 경유지 제안)

- 상태: 열림
- 보낸 사람: 개발 → @모두

## 무엇을 하나
운전 중 "나 똥마려" · "화장실 급해" · "졸려" · "배고파" · "커피" · "기름" 같은 말을 하면, 에이전트가 **도구를 스스로 불러** 경로 앞쪽에서 들를 곳을 찾고
"다음 기흥휴게소 부산방향까지 8.4km, 약 6분이에요. 경유지로 넣을까요?"를 큰 카드 한 장 + 음성으로 묻는다. "응"(또는 "예" 버튼)이면 내비 경유지로 넣는다.

## 구조
| 부분 | 위치 | 맡는 일 |
|---|---|---|
| 도구 루프 | `app/.../agent/roadside/RoadsideAgent.kt` | LLM에 도구 정의를 주고 최대 3번 도구 호출 → 실행 → 결과를 돌려준다 (Dispatchers.Default/IO, 전체 7초 예산, 1.5초 넘으면 "찾아볼게요") |
| LLM 입구 | `agent/roadside/LlmChat.kt` | `LlmChat.chat(messages, tools)` → 글 또는 tool_calls. 구현 `OpenAiCompatChat`(HTTP · 해석은 Rust `roadside::llm_chat`, 기억 에이전트와 같은 클라이언트) |
| 계산 · 규칙 | `core-rs/src/roadside.rs` (+ `roadside_tests.rs`) | 흔한 말 규칙, 경로 앞쪽 거리 · 우회 · 도착 분, 반대 방향 휴게소 거르기, 카카오 응답 해석, 도구 정의(중립 JSON 스키마) · 인자 검증, JSON 예비 호출 해석, 규칙 답 문장 |
| 기기 목록 | `core-rs/src/roadside_places.json` | 전국 고속도로 휴게소 215곳(화물차휴게소 21곳은 찾기에서 뺌) + 졸음쉼터 253곳, 공공데이터포털 표준데이터 (아래 출처). 만드는 법 `scripts/data/build_roadside.py` |
| 화면 | `ui/agent/RoadsideCards.kt`, `AgentPanel.kt` | 주행: 큰 카드 1장(이름 · "8.4km · 6분 앞" · 다른 선택 한 줄) + 예/아니요. 정차: 3개까지 |
| 연결 | `AgentViewModel.kt` | 규칙이 알아들은 말이면 기억 에이전트 대신 길 위 에이전트로. "응/아니"는 지금 차례의 제안으로 처리 |

도구 (모델은 해석 · 계획만, 실행은 운전자 "응" 뒤 앱이):
- `get_drive_context` — 주행 · 속도 · 위치 · 방향 · 내비 목적지와 남은 거리/분 · 쉬지 않고 달린 분 · 연료/배터리 (시스템 프롬프트 [상황]에도 미리 넣어 한 번을 아낀다)
- `search_along_route(category, max_detour_km?, limit?)` — rest_area · drowsy_shelter · toilet · gas · ev_charger · cafe · food · convenience
- `search_memory(query)` — 내 기록에서 ("늘 가던 휴게소")
- `propose_waypoint(place_id)` / `navigate_to(place_id)` — 제안만. 경유지는 기존 것 1개 + 새 것 = 2개까지

"경로 앞쪽": 내비 목적지가 있으면 카카오모빌리티 길찾기(중계)로 경로 꺾은선을 받아 쓰고(NaviHelper는 경로 좌표를 주지 않는다), 없으면 진행 방향 직선(60km).
방향 시설은 공공데이터 도로노선방향(휴게소 "기흥(부산)" · 상행/하행, 졸음쉼터 "서울기점 + 부산종점" → 부산방향)으로 정한 도시 쪽으로 가는 중일 때만, 도시를 모르면 진행 방향 오른쪽일 때만 낸다.
종류는 시설 유무로 고른다: 화장실 → 화장실유무(휴게소 · 졸음쉼터), 주유 → 주유소유무, 충전 → 전기차충전소유무, 배고파 → 음식점유무(대표 음식이 있으면 한마디 덧붙임, 지금 표준데이터에는 비어 있음), 편의점 → 매점유무. 카페는 표준데이터에 없어 카카오로만.

빠른 길: `roadside_need`가 알아들은 종류는 LLM을 기다리지 않고 동시에 미리 찾는다. LLM이 없거나 실패하면 그 결과로 규칙 문장(`roadside_pick`)을 낸다.
운전 중 답은 LLM 글이 80자 안이고 묻는 말로 끝날 때만 쓰고, 아니면 규칙 문장 (숫자를 지어내지 않게).

## 시연 (디버그 빌드)
```powershell
powershell -ExecutionPolicy Bypass -File scripts\vc.ps1 -Gear Drive -Speed 90      # 주행 화면
adb shell am broadcast --user 10 -n app.eodiyeotji/.agent.roadside.RoadsideDebugReceiver --es scenario gyeongbu --es say "'나 똥마려'"
adb shell am broadcast --user 10 -n app.eodiyeotji/.agent.roadside.RoadsideDebugReceiver --es say "졸려"
adb shell am broadcast --user 10 -n app.eodiyeotji/.agent.roadside.RoadsideDebugReceiver --es say "응"     # 경유지로 넣기
adb shell am broadcast --user 10 -n app.eodiyeotji/.agent.roadside.RoadsideDebugReceiver --ez clear true  # 실제 값으로
adb logcat -s EodiRoadside   # 도구 호출 기록 (어느 도구 · 몇 ms)
```
`scenario gyeongbu` = 경부고속도로 수지 부근, 남쪽 100km/h, 목적지 대전역 (에뮬레이터는 내비 경로 · 방향을 만들 수 없어 바꿔 끼운다).
띄어쓰기가 있는 말은 `"'나 똥마려'"`처럼 두 번 감싼다 (adb shell이 한 번 벗긴다).

## Gemini로 바꿀 때
- 중계 서버에 `/gemini/v1beta/openai/...` 경로를 추가해 키를 서버에서 붙인다 (APK에 키 없음).
- Gemini의 OpenAI 호환 주소는 `tools` / `tool_calls` 모양이 같아 `LLM_BASE_URL`(…/gemini/v1beta/openai) · `LLM_MODEL`만 바꾸면 된다.
  단 지금 요청 본문에 llama.cpp 전용 `cache_prompt` · `chat_template_kwargs`가 들어간다(`agent/llm.rs` `body`) → Gemini가 모르는 필드로 거절하면 공급자별로 빼야 한다 (확인 안 함).
- 도구 정의는 중립 JSON 스키마(`roadside_tool_specs`)라 Gemini 네이티브 `functionDeclarations`로도 그대로 옮길 수 있다 (`LlmChat` 구현 하나 추가).
- JSON-in-prompt 예비 길(`roadside_parse_json_call`)은 tool_calls가 비었을 때만 쓰는 Qwen용이다.
