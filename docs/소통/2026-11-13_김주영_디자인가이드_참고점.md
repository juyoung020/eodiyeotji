# Pleos Connect 디자인 가이드 — 우리 앱이 참고 · 도입할 점

- 작성: 김주영 · 2026-11-13
- 읽은 범위: `refs/pleos-docs/guides/connect/docs-design/` 아래 **42개 파일 전부** (Introduction 4 · getting-started 2 · foundations 8 · components 26 · Experiences 2)
- 분석만 했다. 앱 코드는 고치지 않았다.
- 범위 밖 (다른 담당이 보는 중): 글자 크기 · 글 길이(mm 기준, 3줄 · 80자 규칙) → 타이포 담당 / DO · 주행 제한 · 생명주기 · 권한 · 멀티윈도 동작 → 앱 설계 가이드 담당. 아래에서는 겹치는 곳만 한 줄로 가리킨다.

> **주의 — 가이드의 수치 대부분은 그림 속에 있다.** 마크다운으로 받은 사본에는 색 값(Color1~24), 글꼴 크기표, easing · duration 표, 버튼 · 아이콘 크기가 전부 이미지로만 있어 글자로 남아 있지 않다. 글로 확인된 숫자는 아래에 적은 것이 전부다 (그림자 3단계, 토스트 24dp · 792/712, 아이콘 48dp 격자, 상태 바 40dp, 누름 95%, 응답 0.25초, 대비 4.5:1, Gleo 대기 2초 · 5초, OSD 2초, 최소 글자 12sp). 정확한 값이 필요하면 **Figma 원본**(아래 3절)을 받아야 한다.

## 4. 가이드 기준으로 이미 잘 하고 있는 것

- **낮/밤 자동 전환** — 시스템 모드를 따르고 지도도 낮/밤 스타일로 바뀐다 (`ui/theme/Theme.kt:86`, `Color.kt:147-`). 가이드 "야간/주간 모드 지원"과 일치.
- **의미 단위 색 토큰 + 테마 무관 색 분리** — `ink`/`onInk`가 가이드의 Static color, `scrim`이 Dim 역할 (`Color.kt:62-67`). 토큰을 "단일 출처"로 쓰는 구조가 Design Token 문서 취지와 같다.
- **대비 기준을 토큰에 명시** — 4.5:1 / 3:1 (`Color.kt:12`).
- **누름 축소 반응** — 가이드의 shrink effect와 같은 방식(`ui/common/Motion.kt:25`, 96% → 95%만 맞추면 됨).
- **차량 터치 76dp 기준** (`Theme.kt:31`), 토스트 · 버튼 최소 높이에도 적용(`ShareNotice.kt:120`).
- **시스템 Toast 대신 앱 창 안 알림** — AAOS에서 Toast가 안 보이는 문제를 피했고, `liveRegion`으로 접근성도 챙김 (`ShareNotice.kt:45-48,116`).
- **Gleo와 같은 흐름의 에이전트 화면** — 사용자 말 말풍선 → 응답 문장 → 실행 버튼 + 후보 목록 (캡처 `guide_now.png`), proactive suggestion(먼저 말 걸기)도 이미 있음.
- **음성 시작 · 취소를 손으로도** — 마이크 버튼 · 취소 (`AgentVoiceLayer.kt:50-55`), 가이드의 "시작 · 종료 · 중단은 수동 실행 가능"과 일치.
- **내비 음성과 겹치지 않기** — 안내 음성 · 듣는 중이면 제안을 미룸 (`ProactiveCenter.kt:199,294`).
- **기록 알림은 최저 우선순위** (`RecordingService.kt:307`) — "필요할 때만 알림" 원칙과 맞음.
- **시스템 영역(상태 바 · GNB · Driving view)을 앱 안에서 흉내 내지 않음.**
- **움직임은 graphicsLayer만** 써서 재구성 없이 가볍게 (`Motion.kt:19`) — 성능 원칙과 가이드의 "짧고 부드럽게"를 같이 만족.
