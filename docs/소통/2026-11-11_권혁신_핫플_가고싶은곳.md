# 핫플 · 가고 싶은 곳 — 코어만 먼저 올림 (LLM 추천에 붙여 쓸 것)

- 상태: 열림
- 보낸 사람: 권혁신 → @김주영

카톡에서 얘기한 "초반엔 이용자가 없으니 인스타 핫플로 채우고, 그 위에 우리 이용자가 실제로 간 걸 표시"를 Rust 코어에 넣었어 (`core-rs/src/hotplace.rs`, DB 버전 17).
화면과 에이전트 도구는 **안 건드렸어.** 네가 LLM 추천("주변 음식점 추천해줘")을 만들고 있어서 겹칠까 봐 데이터 함수만 올린 거야.

## 지금 있는 것

| 함수 | 하는 일 |
|---|---|
| `hot_places(near, limit)` | 핫플 목록. 곳마다 분류(음식 · 카페 · 여행), 꼬리표, **실제로 다녀온 이용자 수**, 리뷰 수 · 별점, 내가 간 날, ♥ 여부 |
| `add_wish_place(place, source, url, now)` | 가고 싶은 곳에 넣기 (핫플 ♥, 또는 폰 공유로 받은 곳). 같은 곳은 한 번만 |
| `wish_places()` / `remove_wish_place(id)` | 가고 싶은 곳 목록 · 빼기 |
| `wish_places_near(center, radius_m)` | 근처의 아직 안 가 본 가고 싶은 곳 (가까운 순) |
| `parse_shared_text(text)` | 다른 앱에서 공유로 받은 글 → 주소 · 출처(인스타 · 네이버지도 · 카카오맵) · 장소 이름 힌트 |
| `pin_kind(category)` | 장소 분류 글자 → 음식 / 카페 / 여행 (지도 핀용) |

- "실제로 다녀온 이용자 수"는 그 장소에 리뷰를 썼거나 그 장소가 든 코스를 올린 서로 다른 작성자 수야. 리뷰 · 코스는 내 기록에서만 올릴 수 있으니까 진짜 다녀온 사람이야.
- LLM 추천에 붙일 때: `hot_places(지금 위치 반경, k)` 결과를 그대로 넘기면 "근처 카페 핫플" 답에 "이용자 5명이 실제로 다녀왔어요"를 붙일 수 있어.

## 알아 둘 것 (카톡에서 나온 얘기)

- **핫플 목록은 시연용 예시야.** 시연 커뮤니티 장소 중 12곳을 골라 넣었어. 인스타그램은 장소나 인기 게시물을 내주는 공개 API가 없는 걸로 알고 있어 (비즈니스 계정용 API는 해시태그 검색 정도). 네가 알아본다고 했으니 결과 나오면 여기 답 달아 줘. 화면에는 "예시"라고 밝히는 게 맞아.
- **카카오 별점으로 거르기는 어려워.** 카카오 로컬 API 응답에는 별점이 없는 걸로 알고 있어 (이름 · 분류 · 주소 · 좌표 · 장소 주소만). 그래서 "3점 미만 거르기"는 우리 리뷰 별점(`avg_rating`)으로 하는 게 현실적이야.
- **지나갈 때 띄우는 알림은 뺐어.** 광고 같다는 말이 맞는 것 같아서, `wish_places_near`는 함수만 두고 아무 데서도 안 불러. 여행지를 목적지로 잡았을 때만 쓰거나, LLM이 물어봤을 때만 쓰면 될 듯.

## 같이 정할 것

1. 핫플을 어디에 보일지: 커뮤니티에 탭 하나 / 지도 핀(음식 · 카페 · 여행) / LLM 답에만
2. 폰 공유로 받는 화면(인스타 게시물 → 장소 이름 찾기 → 저장)을 내가 만들지. 받은 글에서 장소 이름 뽑기는 LLM에 맡기면 좋을 듯
3. 영상은 네가 고치는 중이라 나는 안 건드려. 초안 보고 적은 의견은 카톡으로 보낸 정리 4번 참고
