## 핵심 요약

- **외부 API를 섞어 써도 되고, 공용 인터넷 연결도 된다.** → 공식 SDK 5종에 없는 LLM도 서버에서 외부 API로 호출 가능
- **개발·테스트 단계에서는 SDK 권한 승인이 필요 없다.** `AndroidManifest`에 `uses-permission`만 선언하면 에뮬레이터에서 바로 호출됨. 승인은 앱마켓 배포 심사 때만
- **2차 PT에서 실차 시연은 없다.** Pleos Connect 에뮬레이터 + **Virtual Console**(차량 상태를 가짜로 바꾸는 도구)로 검증

## 1. 공모전 안내 — 사이트에 없던 내용

일정·상금·제출물 기본은 `02_공모전_개요.md`, `05_제출방법_양식.md`, `07_심사기준_시상.md` 참고.

- **복수 출품 가능, 개수 제한 없음.** 같은 작품을 고쳐 내는 "수정 제출"과는 별개. 작품은 앱명으로 구분
- **메일 제목 형식이 자료마다 다름**
  - 설명회 화면: `[차량용 앱 개발 공모전] 앱명_팀명(개인은 이름)`, 수정 시 앞에 `[수정제출]`
  - 사이트·접수양식: `[차량용 앱 개발 공모전] 팀명(개인은 성명)_대표자명`
  - → 앱명·팀명·대표자명을 모두 넣으면 안전
- **아이디어 특별상도 개발 산출물 제출 필요.** 완성도가 조금 낮아도 아이디어 혁신성이 크면 받을 수 있는 상

- 숏폼: 차량 안팎 이미지 노출은 최소화, 초상권·저작권은 응모자 책임

## 3. 개발 착수 안내

**플랫폼**
- Pleos Connect: 현대·기아·제네시스 차세대 인포테인먼트, AAOS(Android Automotive OS) 기반 → 안드로이드 개발 경험이 그대로 통함
- 스마트폰 앱과 다른 점: 주행 중/정차 중, 차량 상태, **운전자와 동승자 중 누가 쓰는지**까지 고려해야 함
- 앱마켓 취지: 폰 앱을 차 화면에 옮기는 게 아니라 "차량이라서 더 유용해지는 앱" (예: 배터리 상태 + 이동 경로 결합, 차량 상황에 맞춘 개인화)

**개발 시작 순서 (권장)**
1. Playground Docs의 **Getting Started** 먼저: Android Studio 새 프로젝트 → Pleos Connect 에뮬레이터 → Vehicle SDK 연동 → 첫 차량 API 호출 (예제: 도어 상태 읽기)
   - 로컬 사본: `refs/pleos-docs/guides/connect/getting-started/`
2. 첫 목표는 "차량 API 하나를 정상 호출"
3. 기획 전에 세 질문에 답하기
   1. 차량 사용자의 어떤 문제를 푸나
   2. 그때 어떤 차량 정보·기능이 필요한가
   3. Playground SDK·개발환경으로 어떻게 구현하나
- 환경: Java/Kotlin, Android API 28+, Gradle 8.0+, 문서에 적힌 SDK 버전·에뮬레이터 확인

**SDK 소개 중 포인트**
- Vehicle: 도어, 주행 정보, 배터리·충전, 공조 등 조회 + 권한에 따라 일부 제어
- NaviHelper: 목적지·경유지·경로 요청 → 내비 앱을 새로 안 만들고 차량 내비와 연동 (예: 여행 추천 장소를 바로 목적지로)
- TTS / STT / FusedLocation: 음성 중심 UX, 위치 기반 서비스
- **SDK를 많이 쓰는 게 목적이 아니다.** 문제 해결에 필요한 SDK를 골라 핵심 기능에 어떻게 쓰는지 분명히 보여줄 것
- 2차에 실제 동작 앱이 필요하니, 처음부터 다 만들기보다 **차량에서만 줄 수 있는 핵심 가치 하나**를 정의하고 그걸 동작하는 기능으로 먼저 보여줄 것

**권한**
- 개발 단계: 승인 없이 매니페스트 `uses-permission` 선언만으로 에뮬레이터에서 호출 가능 (선언 안 하면 호출 안 됨)
- 배포 단계: Pleos 앱마켓 심사에서 "승인된 권한만 선언했는지" 확인 → 승인 안 된 권한이 있으면 심사 불통과

**에뮬레이터 + Virtual Console**
- 에뮬레이터: Android Studio에서 차량용 앱 실행·검증, SDK 연동 기능도 지원 범위 안에서 테스트
- Virtual Console: 기어 변경, 도어 열고 닫기, 배터리 충전량 변경 등 차량 상태·이벤트를 가상으로 만들어 앱 반응 확인
- 설치·설정은 개발 문서에 단계별로 있음

## 4. 기술 Q&A

| 질문 | 답 |
|---|---|
| 외부 API를 섞어 써도 되나 | **가능. 공용 네트워크 연결도 가능** |
| SDK 권한 승인 | 공개된 5종(Vehicle, NaviHelper, STT, TTS, FusedLocation) 모두 개발 단계에선 선언만으로 사용. 승인은 앱마켓 배포 심사 때 |
| 운전자 주의 분산(Driver Distraction) | 현장 답변 없음 → 추후 정리해서 전달 예정 |

- 추가 질문: 접수 메일(appdevchallenge@hyundai-partners.com)로 받음. 질문이 몰리면 모아서 FAQ에 게시
- 마지막 당부 4가지
  1. 11/15까지 기획서 + 참가자 전원 서명 동의서, 메일은 전원 CC
  2. 개발 산출물은 선택이지만 가산점, PT 대상팀은 PT 전 개발 완료
  3. 차량 환경만의 사용자 경험에 집중, SDK·API를 핵심 기능과 연결
  4. Playground 사용 경험 온라인 설문 (QR은 사이트 팝업), 좋은 피드백엔 소정의 선물

## 우리 기획에 주는 의미

| 전에 걱정한 것 | 설명회 답 | 결론 |
|---|---|---|
| LLM SDK가 공식 5종에 없음 | 외부 API·인터넷 허용 | 서버에서 외부 LLM API 호출로 "그때 어디 갔지?" 답변·보고서 초안 가능 |
| 외부 서버(DB) 통신 | 공용 인터넷 허용 | Supabase 등 외부 백엔드 사용 가능 |
| Odometer 등 권한 승인 | 개발 단계 승인 불필요 | `pleos.car.permission.CAR_DRIVE` 선언만으로 에뮬레이터 테스트 |
| 실차 없이 시연 | 실차 시연 자체가 없음 | Virtual Console로 주행 값을 바꿔가며 시연 영상 촬영 |
| 운전 중 조작 규정 | 아직 답 없음 | 기획서에 "주행 중 화면 최소화, 음성만" 안전 규칙을 먼저 명시 |
| 생성형 AI로 개발 | 허용, PT에서 직접 설명 | 구조·로직을 팀원 모두 이해하고 있어야 함 |
