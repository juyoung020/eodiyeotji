### ① 앱 한 줄 소개

> 시동만 걸면 차가 모든 이동을 기억해 두고, "그때 거기 어디였지?" 한마디에 그날의 장소를 찾아 바로 안내해 주는 차량용 드라이브 기억 앱

### ② 기획 배경

**주목한 순간: "분명 갔었는데, 거기가 어디였더라?"**

- 운전자는 차로 많은 곳을 다니지만, 다녀온 곳을 다시 찾는 건 어렵다.
  - 폰 타임라인 앱은 **날짜를 알아야** 찾을 수 있다. 그런데 사람은 "작년 여름쯤 가족이랑 갔던 바다"처럼 날짜가 아니라 **상황**으로 기억한다.
  - 매일 반복되는 출퇴근 기록이 쌓여서, 정작 기억하고 싶은 **특별한 날이 묻힌다**.
  - 폰은 "어디에 있었나"만 안다. 누구와 갔는지, 비가 왔는지, 얼마나 달렸는지는 모른다.
- 운전 중에는 폰을 꺼내 기록을 뒤질 수도 없다. 그래서 "지난번 그 식당 가자"는 말이 나와도 결국 포기하거나 정차 후 한참 검색한다.
- 반면 차는 시동, 주행 거리, 탑승 인원, 와이퍼, 정차 같은 **이동의 맥락**을 이미 알고 있다. 이 데이터를 쓰면 사용자가 아무것도 하지 않아도 "그날"을 기억해 둘 수 있다.

**왜 해결해야 하나**

- 여행·나들이·출장의 동선은 다시 가고 싶을 때, 남에게 추천할 때, 업무로 보고할 때 반복해서 필요하다.
- 특히 차로 일하는 사람(영업·현장 점검·방문 서비스)은 다녀온 곳을 출장 보고서와 업무용 승용차 운행기록부로 다시 적어야 한다. 지금은 기억을 더듬어 수기나 엑셀로 쓴다.
- 차량 화면과 음성은 운전 중에도 안전하게 쓸 수 있는 유일한 창구다. 폰으로는 줄 수 없는 경험이다.

### ③ 앱 주요 기능 및 차량 특화 요소

**기록 → 기억 → 공유** 세 단계로 동작한다.

**1. 기록 — 시동만 걸면 자동으로**
- 시작 버튼이 없다. 시동을 걸면 기록이 시작되고, 끄면 하루 주행이 정리된다.
- 차에서만 아는 데이터로 기록한다.

| 기록 | 어떻게 아나 | 쓰임 |
|---|---|---|
| 출발 · 경유 · 도착, 경로 | FusedLocation 위치, NaviHelper 경로 이벤트 | 타임라인의 뼈대 |
| 머문 곳 | 정차 시간 + 도어 열림 (Vehicle) | "○○식당에서 1시간" |
| 함께 탄 인원 | 좌석별 탑승 감지 (Vehicle Seat) | 혼자 / 둘 / 가족 단위로 출근·데이트·가족여행 자동 분류. 누구인지는 사용자가 태그 |
| 날씨 | 와이퍼 상태, 실내외 온도 (Vehicle) | "비 오는 날 해안도로" |
| 거리 · 시간 · 전비 | Odometer 트립, Fuel / EvBattery (Vehicle) | "왕복 420km, 전비 6.1km/kWh" |
| 집 · 회사 | NaviHelper 즐겨찾기 HOME / OFFICE | 출퇴근은 접어서 타임라인을 깔끔하게, 공유 시 자동으로 가림 |

**2. 기억 — 요약하고, 말로 찾고, 지나가면 떠올린다**
- **하루 요약:** 하루가 끝나면 AI가 "가족 4명 · 강릉 바다 · 비 조금 · 왕복 420km"처럼 짧은 이야기와 태그로 정리한다.
- **말로 찾기:** 운전 중 "작년 여름에 바다 갔던 데 어디였지?" → 음성으로 답하고 "거기로 안내해줘" 한마디로 내비 경로 연결.
- **지나가면 떠오르는 기억:** 예전에 들렀던 곳 근처를 지나면 "3년 전 이 길로 가족이랑 바다 갔었어요"라고 짧게 알려준다.
- **N년 전 오늘:** 시동을 걸면 "1년 전 오늘은 제주 해안도로를 달렸어요" 카드 1장.

**3. 공유 — 실제로 다녀온 길만 코스로**
- 하루 기록을 버튼 하나로 코스로 만든다. 다른 사람은 그 코스를 눌러 **내 내비에 바로 경로로** 넣는다.
- 전기차라면 "이 코스, 내 차로 갈 수 있나?"를 도착 시 예상 배터리로 보여준다 (NaviHelper `requestTrip`).
- 실제 주행 기록에서 나온 코스라 광고성 추천보다 믿을 수 있다.
- **실제 방문 기준 장소 순위:** 내비 목적지로 찍기만 한 횟수가 아니라, 사용자들이 실제로 도착해서 머문 기록으로 "근처에서 많이 머문 식당·카페" 순위를 만든다. 운전 중 "근처 맛집"을 물으면 1위를 음성으로 알려주고 바로 안내한다.

**4. 업무 모드 — 같은 기록으로 보고서까지**
- 업무 운행과 개인 운행을 나눈다 (근무 시간·거래처 목적지 규칙 + 음성 "업무" 한마디).
- 운전 중 도착하면 "방문 목적을 말씀해 주세요" → 한마디로 목적을 남긴다 (SpeechToText).
- 방문지별 도착·출발 시각과 트립 거리(Odometer)로 출장 보고서와 업무용 승용차 운행기록부 초안을 만든다.

**차량 특화 요소 정리**
- 폰으로는 알 수 없는 탑승 인원 · 와이퍼 · 전비 · 정차 데이터로 기억을 만든다.
- "그 길을 지날 때"라는 이동 맥락에서 회상한다.
- 찾은 장소를 차량 내비로 바로 잇는다.
- 운전 중에는 음성만, 정차 중에는 화면 — 주행 상태에 맞춰 화면이 바뀐다.

### ④ 주요 사용 시나리오

**시나리오 1. 주말 가족 나들이 (기록 → 회상)**

| 순간 | 상황 | 앱 동작 |
|---|---|---|
| 토요일 아침 | 가족 4명이 타고 시동 | 자동 기록 시작, 별도 조작 없음 |
| 하루 동안 | 휴게소 → 해변 → 식당 → 카페 | 머문 곳·탑승 인원·날씨·거리 자동 기록 |
| 저녁 | 집 도착 후 시동 끔 | AI가 "가족 4명 · 강릉 바다 여행" 요약과 태그 생성 |
| 1년 뒤 같은 날 | 시동을 켬 | "1년 전 오늘 강릉 바다에 다녀왔어요" 카드 1장 |

**시나리오 2. 운전 중에 기억 찾기 (주행 중 = 음성만)**

1. 운전 중 동승자가 "작년에 갔던 그 순두부집 어디였지?"라고 묻는다.
2. 운전자가 "어디였지, 작년 강릉 순두부집" 하고 말한다 (SpeechToText).
3. 앱이 "2025년 8월 14일 점심에 들른 초당순두부예요. 안내할까요?"라고 답한다 (TextToSpeech).
4. "안내해줘" → 차량 내비 목적지로 바로 설정된다 (NaviHelper). 화면은 큰 카드 1장만 보인다.

**시나리오 3. 정차 중에 코스 공유하고 따라가기 (정차 중 = 화면)**

1. 주차 후 타임라인에서 지난 주말 기록을 열고 "코스로 공유"를 누른다. 집 근처 구간은 자동으로 가려진다.
2. 다른 사용자가 "가을 단풍 드라이브"로 검색해 그 코스를 연다.
3. 전기차 사용자에게는 도착 시 예상 배터리가 함께 보인다. "따라가기"를 누르면 경유지가 내비에 들어간다. 경유지가 많으면 구간별로 이어서 안내한다.

### ⑤ 개발 계획

**구현 구조: "Rust가 엔진, Kotlin이 계기판"**

| 계층 | 기술 | 맡는 일 |
|---|---|---|
| 앱 | Kotlin + Jetpack Compose + Hilt (Pleos 공식 샘플과 같은 스택) | 주행 / 정차 화면, Pleos SDK · AAOS API 연결 |
| 코어 | Rust (`eodi-core`, UniFFI로 Kotlin 연결) | 주행·머문 곳 판정, 경로 단순화, 기기 안 저장·검색(SQLite + R-tree + FTS5), 회상 후보 계산, 코스 구간 분할 |
| 지도 | MapLibre Native + 기기 내 지도 파일 | GPU로 경로 그리기, 오프라인 우선 |
| 서버 | 외부 LLM API (설명회에서 외부 API · 인터넷 허용 확인) | 하루 요약, 자연어 질문 → 검색 조건 변환. 검색 자체는 기기 안에서 100ms 이내 |

**SDK / API 사용 계획 (공식 SDK 5종 모두 핵심 기능에 사용)**

| SDK / API | 사용하는 기능 | 쓰는 곳 |
|---|---|---|
| **FusedLocation** | 위치 구독, 지오펜스(`addProximityAlert`) | 자동 기록, "지나가면 떠오르는 기억" |
| **NaviHelper** | 경로 시작·도착 이벤트, 즐겨찾기 HOME/OFFICE, `requestRouteWithWaypoints`, `requestTrip` | 기록 보조, 출퇴근 분류·가림, 찾은 장소 안내, 코스 따라가기, 도착 시 예상 배터리 |
| **Vehicle** | Seat(탑승), Door, Wiper, Odometer(트립), Fuel / EvBattery | 동승 인원·머문 곳·날씨·거리·전비 기록 |
| **SpeechToText** | 음성 질문 인식 | 운전 중 "어디였지?" 검색 |
| **TextToSpeech** | 답변·회상 안내 읽기 | 검색 결과, 회상 안내 (내비 음성과 겹치지 않게 오디오 포커스 관리) |
| AAOS 표준 Car API | `IGNITION_STATE`, `CarUxRestrictions` | 시동 기준 기록 시작·끝, 주행 / 정차 화면 전환 |

**기술 제약과 해결**
- NaviHelper 경유지는 최대 2개 → 코스를 구간으로 나누고, 도착 이벤트가 오면 다음 구간을 요청한다.
- Vehicle · FusedLocation은 차종마다 지원이 다르다 → `checkXxxCapabilities()` / `isSupported()`로 확인한 뒤 기능을 켠다.
- 실차 없이 개발한다 → Pleos Connect 에뮬레이터 + Virtual Console로 기어·주행 값을 바꿔가며 검증한다.

**개발 범위**

| 단계 | 범위 |
|---|---|
| 1차 | 기획서, 화면 시안, 에뮬레이터에서 기록 → 요약 → 검색 흐름 시연 영상 |
| 2차 PT | MVP: ① 자동 기록 ② AI 하루 요약 + 음성 검색 ③ 지오펜스 회상 안내 ④ 코스 공유 목록 + 따라가기 |
| 이후 | 업무 모드(보고서·운행기록부 초안), 실제 방문 기준 장소 순위, 가게 제휴, 지자체 테마 코스, 연말 결산 |

**안전 · 개인정보**
- 주행 중에는 음성 + 큰 카드 1장만. 피드·리뷰 쓰기·긴 목록은 정차 중에만 (Pleos 운전자 주의 분산 가이드 기준).
- 기록은 기기 안에 저장하고 기본 비공개. 공유는 코스 단위로 직접 고를 때만, 집·회사 근처는 자동으로 가리고 동승자 정보는 공유하지 않는다.

### ⑥ 기대효과 및 발전 가능성

**사용자에게 주는 가치**
- 아무것도 안 해도 "그날"이 남는다. 날짜를 몰라도 상황으로 찾을 수 있다.
- 운전 중에도 안전하게 기억을 찾고, 찾은 곳으로 바로 간다.
- 남의 실제 주행 코스를 믿고 따라갈 수 있다.

**타깃 고객**

| 고객 | 왜 쓰나 |
|---|---|
| 주말 드라이버 · 가족 단위 | 나들이·여행 기록과 회상, 다시 가기 |
| 전기차 오너 | 전비·충전까지 검증된 코스 |
| 커플 · 친구 | 함께 간 곳 모아보기, 코스 공유 |
| 차로 일하는 직군 (영업·현장 점검·방문 서비스) | 같은 기록으로 출장 보고서·운행기록부 초안 → 업무 모드. 회사가 비용을 내는 고객이고, 혼자 써도 바로 가치가 있다 |

**예상 MAU 【확인: 숫자는 가정, 근거 보강 필요】**
- Pleos Connect는 2026년 2분기부터 신차에 적용되고, 현대차그룹은 2030년까지 2,000만 대 이상으로 넓힐 계획이다.
- 가정 예시: 출시 1년 차 탑재 차량 100만 대 × 앱마켓 설치율 5% × 월 사용률 50% ≈ **MAU 2.5만**. 탑재 차량이 늘수록 같이 커진다.

**리텐션(Retention, 재사용률)**
- 시동만 걸면 기록되니 "앱을 다시 열어야 하는 이유"를 따로 만들 필요가 없다.
- 기록이 쌓일수록 회상("N년 전 오늘", 지나가면 떠오르는 기억)과 연말 결산의 가치가 커져서, 오래 쓸수록 떠나기 어려워진다.

**확대 계획 · 사업 모델**
- 지역 가게 제휴: 실제 방문 순위와 인기 코스에 들어간 식당·카페를 "코스 공식 맛집"으로 노출 (광고 표시)
- 지자체 · 관광공사 테마 코스 ("가을 단풍 드라이브 10선")
- EV 충전 사업자 제휴: 코스 위 충전소 추천
- 프리미엄: 연말 결산 영상, 기록 무제한 보관
- 업무 모드 기업 구독: 차량 대수 또는 사용자 수 기준. 출장 보고서·운행기록부 초안, 관리자 승인 화면
- 출시 단계에서 위치기반서비스사업자 신고를 마치고 서비스한다 (R5)
