# 70 기억 · 검색 · 기억 에이전트 설계

> 근거: `planning/01_아이디어_확장.md`(②기억: 하루 요약·자연어 검색·그날 다시 달리기), `README.md`, `docs/00_plan.md` 개발 순서 6·7단계, `docs/60_앱_아키텍처.md`
> 코드 계약: `core-rs/src/memory.rs`, `app/src/main/java/app/eodiyeotji/core/EodiCore.kt`

## 한눈에

```
기록(주행·머문 곳·장소 이름) ─▶ 에피소드(규칙) ─▶ 하루 라벨링(LLM, 하루 1번) ─▶ 검색 색인(FTS5)
                                                                                    │
운전자: "언제 바다 갔었는데 어디였지?" ─▶ 기억 에이전트(LLM + 도구) ──────────────────┘
        답: "1년 전 8월 14일, 가족이랑 경포해변 갔던 날이에요. 그 코스로 안내할까요?"  + 추천 카드
        "응" ─▶ 코스 경로(Rust, 지금 위치에서 최적 순서) ─▶ Pleos 내비 안내(경유지 2개씩 구간)
```

## 1. 에피소드 (Rust, 규칙)

주행과 머문 곳을 사람이 기억하는 단위로 묶는다.

| 종류 | 판단 | 기본 라벨(규칙) |
|---|---|---|
| 출근길 | 집 → 회사 | "출근길" |
| 퇴근길 | 회사 → 집 (중간 들른 곳 포함) | "퇴근길 · 이마트 들름" |
| 볼일 | 생활권 안, 자주 가는 곳 | "동네 볼일 · 이마트" |
| 나들이 | 생활권 밖 당일, 처음이거나 드문 곳 | "성수 나들이" |
| 여행 | 멀리(예: 집에서 80km 이상) 또는 하룻밤 이상 | "강릉 여행" |

- **집 · 회사:** 내비 즐겨찾기(HOME/OFFICE, NaviHelper `getBookmarkInfo`)가 1순위. 없으면 기록에서 추정한다(밤에 가장 오래 머문 곳 = 집, 평일 낮에 가장 오래 머문 곳 = 회사).
- **코스:** 나들이 · 여행의 들른 곳 순서가 곧 코스다. 따로 저장 버튼이 없다.

## 2. 하루 라벨링 (LLM, 하루 1번)

- 입력: 하루치 사실(`DayFacts`) — 에피소드 종류, 들른 곳 이름 · 분류 · 지역 · 처음 방문 여부, 시간대, 거리 (나중에 동승 인원 · 와이퍼).
- 출력(`DayEnrichment`): 하루 제목, 한두 문장 이야기, 검색 태그(동의어 포함), 에피소드별 제목 · 태그.
  - 예: "비 오는 날 강릉 순두부 원정" / "퇴근길에 성수 카페 한 잔" / 태그 `바다 해변 해수욕장 여행 가족 맛집 순두부`
- 출퇴근뿐인 평범한 날은 LLM을 부르지 않고 규칙 제목("평소 출퇴근")으로 끝낸다.
- 결과는 기기 DB에 저장하고 다시 부르지 않는다. 그날 기록이 크게 바뀌면(새 나들이) 다시 라벨링한다.

## 3. 기억 검색 (기기 안, 하이브리드)

- 색인: 하루 제목 · 이야기 · 태그 + 에피소드 제목 · 태그 + 들른 곳 이름 · 분류 · 주소를 SQLite FTS5로 색인한다.
- 질의(`MemoryQuery`): 의미어(동의어 확장), 기간, 종류. 순위 = FTS 점수 + 태그 일치 + 처음 방문 · 머문 시간 + 최신성.
- 벡터 검색은 지금 쓰지 않는다. 기록이 1년에 수천 개로 작고, LLM이 저장할 때 태그를 · 찾을 때 동의어를 붙여 "바다 ↔ 해수욕장" 같은 의미 연결을 대신한다. 정확도가 모자라면 임베딩을 같은 DB에 넣고 Rust에서 바로 비교한다(수천 개면 1ms 미만).

## 4. 기억 에이전트 (LLM + 도구)

질문을 고정된 순서로 처리하지 않고, LLM이 도구를 골라 쓴다.

| 도구 | 하는 일 | 연결 |
|---|---|---|
| `search_memories` | 의미어 · 기간 · 종류로 기억 검색 | Rust `search_memories` |
| `get_day` | 하루 상세(에피소드 · 들른 곳) | Rust `episodes_for_day` / `day_detail` |
| `plan_course` | 에피소드 코스를 그날 순서 또는 지금 위치에서 최적 순서로, 내비 구간까지 | Rust `course_route` |
| `navigate` | 코스 · 장소로 내비 안내 시작 (운전자 확인 후) | Pleos NaviHelper `requestRouteWithWaypoints` |
| `courses` | 지금 위치 근처 인기 드라이브 코스 상위 k개 (하트 · 거리), 번호로 이어 고르기 | Rust `recommend_drive_courses` (`core-rs/src/community.rs`, `agent/courses.rs`) |
| `open_in_navi` | 차량 내비에서 장소 검색 화면 열기 | NaviHelper `SearchPlace` |

- 답은 짧은 한국어 한두 문장(운전 중에는 TTS로 읽는다) + 추천 카드(에피소드, 추천 경유지, 지도).
- 안내 시작 같은 행동은 운전자가 "응/안내해줘"로 확인한 뒤에만 실행한다.
- 속도: 도구는 기기 안이라 수 ms. 답은 스트리밍으로 바로 보여 준다. "작년 여름" 같은 날짜 표현은 기기 날짜 기준으로 해석한다.

## 5. 시연 데이터

"1년 전 바다"를 보여 주려면 1년치 기록이 있어야 한다. Rust `seed_demo_data`가 출퇴근 · 주말 볼일 · 나들이 · 여행(1년 전 8월 강릉 가족 여행 등)을 실제 장소 이름과 함께 만든다(디버그 빌드에서만).

## 6. LLM

- 모델: **Qwen3.5-9B** (오픈 모델, `unsloth/Qwen3.5-9B-MTP-GGUF` Q5_K_M 6.7GB)을 llama.cpp `llama-server`로 띄운다 (`scripts/llm/start-llm.ps1`). OpenAI 호환 Chat Completions + 도구 호출.
- 위치: 개발·시연은 이 PC(RTX 5070 Ti)에서 돌리고, 에뮬레이터 앱은 `http://10.0.2.2:8181/v1`로 붙는다. 출시 단계에서는 같은 서버를 `server/`로 옮긴다. 앱 설정은 `local.properties`의 `LLM_BASE_URL`·`LLM_MODEL`.
- 에이전트 반복(모델 호출 → 도구 실행 → 다시 호출)은 앱이 직접 구현한다. 작은 모델용 요령(AI Agent 수업 참고 설계): 도구는 4개로 적게, 도구 호출 이름·JSON 검사 후 틀리면 오류를 도구 결과로 돌려줌, 같은 실패 3번이면 멈춤, 안내 같은 행동은 운전자 승인 후 실행, 도구 결과는 데이터로 감싸 그 안의 지시를 따르지 않음, 큰 결과는 줄여서 넘김.
- 측정(2026-11-06): "작년 여름에 바다 갔었는데 거기 어디였지?" → `search_memories(terms=[바다, 해변, 바닷가], 2025-06-01~2025-08-31)` 호출까지 0.45~0.9초, 생성 170~200토큰/초, MTP 미리 맞히기 적중 약 82%, GPU 메모리 11.3GB.
