## 접수양식 = 기획서: 무엇을 써야 하나

양식은 4부분이다. DOCX · PDF 둘 다 된다. 항목과 순서만 지키면 글꼴 · 표를 바꾸고 이미지 · 도표를 넣어도 된다.

### 01 참가신청서 (운영용, 개인정보는 여기에만)

- 참가 단위(팀) · 참가 부문(대학(원)생 / 일반 — 일반인이 1명이라도 있으면 일반)
- 팀명, 앱명(어디였지), 대표자 성명 · 역할 · 소속(선택) · 이메일 · 휴대폰, 참가 인원, 작성일
- B. 참가 구성원 표: 전원의 성명 · 소속 · 휴대폰 · 이메일 · 담당 역할

### 02 앱 프로젝트 소개 / 심사 자료 (심사는 이 부분으로 한다, 이름 · 연락처 · 소속을 쓰지 않는다)

| 칸 | 써야 할 것 (양식 질문 요약) | 주로 보는 심사 항목 |
|---|---|---|
| 1. 앱 한 줄 소개 | 한 문장 | 전체 |
| 2. 기획 배경 | 어떤 고객의 어떤 불편한 순간인지, 왜 풀어야 하는지 | 창의성 |
| 3. 주요 기능 · 차량 특화 요소 | 핵심 기능, 푸는 문제, 차에서만 되는 새 경험 | 차량특화성 · 창의성 |
| 4. 주요 사용 시나리오 | 누가 · 어떤 상황에서 · 어떻게 (주행 중 / 정차 중 흐름) | 차량특화성 |
| 5. 개발 계획 | Pleos Connect에서 어떻게 만드는지, 개발 범위, **SDK · API 사용 계획** | 기술 활용성 |
| 6. 기대효과 · 발전 가능성 | 타깃 고객, **예상 MAU, Retention Rate**, 확대 계획 | 사업성 |
| 7. 참고자료 (선택, 가산점) | 화면 시안, 시연 영상, GitHub 저장소 링크 | 가산점 |
| 8. 숏폼 링크 (선택, 가산점 없음) | 세로 영상 링크 (특별상 50만 원 별도) | — |

- 분량 제한 없음. 공유 링크 · 첨부에도 개인정보 · 계정 · 실명이 보이지 않게 한다.
- 심사 항목 자세히: `40_평가기준_정리.md`
- 기획서에 쓸 때 지킬 것 (공지 8, `18_공지_08_정리.md`): 공개된 SDK 5종 범위로 쓰고, 문서에 없는 기능은 "향후 계획"으로 적는다. LLM은 외부 API, 음성 인식은 SpeechToText SDK.

### 03 개인정보 수집 · 이용 동의서 · 04 서명

- 대표자 포함 **팀원 전원이 각자** 동의 여부 체크 + 본인 서명 + 날짜. 참조(CC)로 대신할 수 없다.
- 전자서명(패드 · 마우스)과 서명 이미지 넣기 모두 된다.

## 메일로 보내는 것

- 받는 곳: `appdevchallenge@hyundai-partners.com`, **팀원 전원 참조(CC)**
- 제목: `[차량용 앱 개발 공모전] 팀명_대표자명` (다시 낼 때는 앞에 `[수정제출]`, 처음 보낸 메일 주소로, 전체 자료 + 서명한 동의서를 다시 첨부)
- 대표자가 아닌 팀원 메일로 보내도 된다
- 첨부 · 본문:

| 무엇 | 필수? | 메모 |
|---|---|---|
| 작성 · 서명한 접수양식 (DOCX 또는 PDF) | **필수** | 01~04 전부 |
| 시연 영상 | 선택 · 가산점 | 목업 · 프로토타입 · 화면 녹화 모두 인정, 분량 제한 없음 |
| GitHub 저장소 주소 + **최종 커밋 번호(commit hash)** | 선택 · 가산점 | 마감 때까지 비공개 가능, 11/16까지 공개 전환 |
| PPT · PDF · HTML 등 추가 자료 | 선택 | 심사 참고용 |
| 숏폼 링크 | 선택 · 가산점 없음 | 기획서 8번 칸에 적는다 |
