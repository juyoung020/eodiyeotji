# 평가기준 정리

> 공식 사이트의 심사 관련 내용을 한 곳에 모았습니다 (2026-11-05 수집).

## 1. 심사 단계

| 단계 | 일정 | 무엇으로 평가 | 결과 |
|---|---|---|---|
| 1차 서류심사 | 접수 ~11.15 / 발표 11.23 | 접수양식(기획서) + 선택 제출물(가산점) | **20팀** 선정 |
| 2차 최종 PT | 12.03–04 오프라인 (현대차 강남대로사옥 1층 UX스튜디오 서울) | **실제 동작하는 앱 시연 필수** (에뮬레이터 화면 또는 기기) | 12.18 **10팀** 발표 |
| 전시·시상 | 2027.02 현대차그룹 행사 | 순위는 **2차 PT 결과로 확정**, 현장에서 발표 | 대상/최우수/우수/특별상 |

- 세부 배점과 세부 심사 과정은 공개하지 않습니다.
- **2차 PT 심사 기준은 "추후 공지 예정"**입니다 (아직 미공개).
- PT 이후 행사 전까지 오류 수정 정도는 가능하지만, 추가 개발은 순위에 영향을 주지 않습니다.

## 2. 1차 서류심사 평가 항목 (공식 원문)

| 항목 | 구분 | 공식 평가 질문 |
|---|---|---|
| **차량특화성** | 필수 | · 모바일 대비 차량 환경만의 독자적인 가치와 우위를 제공하는가<br>· 주행·정차 맥락 및 차량 기능과 유기적으로 결합되었는가 |
| **창의성** | 필수 | · 기존에 없던 독창적이고 혁신적인 아이디어인가<br>· 운전자 및 동승자의 Pain Points & Needs가 명확히 정의되고 해결 방식이 명확한가 |
| **기술 활용성** | 필수 | · Pleos Playground에서 제공하는 SDK·API를 앱의 핵심 기능과 사용 경험에 적절히 활용했는가 |
| **사업성** | 필수 | · 타깃 고객이 명확하며, 사용자 확보와 지속적인 이용·확대 가능성이 있는가 (타깃 고객 분석, 예상 MAU, Retention Rate, 향후 서비스 확대 계획 등) |
| **[가산점] 개발 산출물** | 선택 | · 프로토타입 시연 영상 (화면 녹화 포함)<br>· GitHub 저장소 링크 (소스 코드 및 APK 포함) |

### 가산점 세부
- 1차 접수 때 시연 영상, GitHub, APK를 함께 내면 **단계별 가산점**을 줍니다 (많이 낼수록 유리).
- 시연 영상은 목업, 프로토타입, 화면 녹화 모두 인정됩니다.
- APK만 따로 내지 말고 **GitHub 저장소에 소스와 APK를 같이** 올립니다. 위치는 `apk/팀명_앱이름_release.apk`, 실행 가능한 release 빌드여야 합니다.
- README에는 앱 이름과 한 줄 소개, 실행 방법, 테스트 환경과 설정, APK 위치를 적습니다.
- 숏폼 링크는 **가산점이 없습니다** (별도 특별상).

## 3. 접수양식 항목 ↔ 평가 항목 대응

접수양식 "02 앱 프로젝트 소개 / 심사 자료"가 곧 심사 자료입니다 (분량 제한 없음, 이 부분에는 개인정보를 적지 않음).

| 양식 번호 | 양식 질문 (원문) | 주로 평가되는 항목 |
|---|---|---|
| 1 | 앱 한 줄 소개 | 전체 |
| 2 | 기획 배경: 어떤 고객의 니즈나 불편한 순간에 주목했으며, 왜 해결이 필요한지 | **창의성** (Pain Point 정의) |
| 3 | 앱 주요 기능 및 차량 특화 요소: 핵심 기능, 해결하는 문제, 차량에서 제공하는 새로운 경험 | **차량특화성**, 창의성 |
| 4 | 주요 사용 시나리오: 누가, 어떤 상황에서, 어떻게 쓰는지 | **차량특화성** (주행·정차 맥락) |
| 5 | 개발 계획: Pleos Connect 환경 구현 방법, 주요 개발 범위, **SDK/API 사용 계획** | **기술 활용성** |
| 6 | 기대효과 및 발전 가능성: 타깃 고객 분석, 예상 MAU, Retention Rate, 확대 계획 | **사업성** |
| 7 | 참고자료 (화면 시안, 시연 영상, GitHub) | **가산점** |
| 8 | 숏폼 링크 | 가산점 없음 (특별상) |

> 위 대응표는 양식 문구와 평가 항목 문구를 맞춰 본 정리이며, 공식 발표된 대응 관계는 아닙니다.

## 4. 공모 주제 예시 (제한 아님)
- 모빌리티 & 라이프 편의: 주행 중에도 끊김 없는 주문·픽업·주차 같은 일상 서비스
- 인카 엔터테인먼트: 주행 맥락과 결합된 몰입형 미디어·사운드
- 스마트 드라이빙 & 안전: 차량 이상 징후 조기 인지, 실시간 안전운전 피드백
- 패밀리 & 동승자 케어: 장거리 이동 중 어린이·가족 동승자 케어
- 그 밖의 주제도 자유

공식 예시 앱 (개발환경 페이지): 음성 메모(STT), 안전운전 점수(Vehicle), 배달 기사용 동선(NaviHelper)

## 6. 숏폼 챌린지 (특별상)
- 1분 세로 영상(Instagram Reels / YouTube Shorts)으로 차량용 앱 아이디어 소개
- 필수 해시태그 `#HMG차량용앱개발공모전` 포함, 해시태그 총 2~3개
- 본상과 **독립적으로** 심사합니다. **선정 기준은 공개되지 않았습니다.**

## 7. 탈락·취소 사유 (유의사항 공지)
- 표절, 다른 공모전 수상작 → 심사 제외
- 기재 내용 허위 → 선정 취소
- 마감 후 제출, 파일 오류·파손 → 지원자 책임
- 수정 제출 때 **전체 자료와 서명한 동의서를 모두** 다시 첨부하고 팀원 전원 CC를 하지 않으면 유효 접수로 인정되지 않음
- 제3자 권리 침해(초상권, 저작권 등) → 수상 취소, 상금 환수
- 현대자동차그룹 임직원은 참가 가능하나 수상 대상에서 제외
- 1차 합격팀이 2차에서 동작하는 앱을 시연하지 못하면 안 됨(필수), 최종 10팀은 2027.02 행사 참석 의무

## 8. (참고) Pleos App Market 앱 심사 가이드 — 공모전 공식 기준 아님

공모전 심사 기준은 아니지만, 수상하면 App Market 탑재 준비를 지원받고 "기술 활용성·차량특화성"을 설득하는 데 쓸 수 있는 기준입니다. 원문은 `refs/pleos-docs/guides/pleos-only/distribute/app-review-guide/`에 있습니다.

| 영역 | 핵심 |
|---|---|
| 운전자 주의 분산 최소화 | 주행 중에는 시선 분산 최소화, 텍스트 입력 최소화, 음성·프리셋 우선, 터치 조작 최적화. Pleos Connect UI 디자인 가이드 준수 |
| 앱 기능·성능 안정성 | 기능이 온전히 동작해야 함, 성능 저하 없어야 함, **Vehicle SDK 권한 사용 심사**, 디스플레이 호환성 |
| 콘텐츠 안전성 | 안전 저해, 선정·폭력, 사행성, 미성년자 보호, 연령 등급 |
| 개인정보·보안 | 개인정보·위치정보를 쓰면 이용약관과 처리방침 필요, 사용자 동의 필수, SDK 악용 금지 |
| 등록정보 | 메타데이터가 정확해야 함 |
